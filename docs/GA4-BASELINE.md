## 指标口径

| 指标 | GA4 名称（Data API） | 定义 | 用在哪 |
|---|---|---|---|
| 跳出率 | `bounceRate` | 1 − 互动率。互动会话是指停留 ≥ 10 秒、有 2 次以上浏览或有转化事件的会话 | 按**着陆页**（`landingPage`）分组，不按页面路径 |
| 互动率 | `engagementRate` | 互动会话 / 会话 | 同上 |
| 每会话浏览数 | `screenPageViewsPerSession` | 浏览次数 / 会话数 | 全站，以及按着陆页分组 |
| 每用户浏览数（人均页数） | `screenPageViewsPerUser` | 浏览次数 / 活跃用户 | 全站 |
| 平均互动时长 | `userEngagementDuration` / `activeUsers` | 每个活跃用户的前台时长 | 全站，以及按页面组 |
| 会话数、用户数 | `sessions`、`activeUsers` | — | 判断样本够不够 |
| 搜索率 | `search` 事件数 / `sessions` | — | 全站 |
| 复制安装命令 | `copy_install` 事件数 / 仓库详情浏览次数 | — | 仓库详情 |

### 口径注意

1. **筛选会算浏览次数。** 查询串变化也会补发 `page_view`，所以在榜单上点筛选、排序或翻页，每点一次就多一次浏览。改版后筛选全改成了链接（chip、下拉、分段），而改版前一部分筛选用 `router.push`。两者都会改查询串，所以都算浏览，但点击习惯可能变了。比较两个浏览数指标时，另算一个「去掉查询串的独立路径数」：用 `pagePath`，不用 `pagePathPlusQueryString`，按会话去重。这个数在 GA4 界面里拿不到，要用探索或 BigQuery（BigQuery 导出有没有开**待确认**）。
2. **跳出率按着陆页看，不按页面看。** 页面路径维度下的跳出率是「从这页开始的会话」的跳出率，GA4 界面里容易看错列。
3. **流量来源要分开。** 同时按 `sessionDefaultChannelGroup` 拆成 Organic Search、Direct、Referral 三组，分别比较，避免外链或爬虫波动把整体数字带偏。
4. **样本量。** 某组 4 周会话数不到 200 时只记数字，不下结论。

## 取数方式

### A. GA4 界面（负责人或有权限的人）

1. 报告 → 互动 → 着陆页。日期选「比较」：改版前那段对改版后那段。
2. 加过滤：着陆页匹配上面各组的正则（在「添加比较」里用「着陆页 + 查询字符串」匹配正则）。
3. 记下各组的会话数、互动率、跳出率、每次会话浏览次数、平均互动时长。
4. 报告 → 互动 → 事件：记下 `search`、`search_result_click`、`copy_install`、`copy_badge` 的次数。
5. 对照组（替代品、博客）用同样方法取。

### B. Data API（脚本化，需要服务账号）

前提**待确认**：要一个 Google Cloud 服务账号，在 GA4 媒体资源里加为「查看者」，再把密钥交给能跑脚本的地方。没配之前只能走 A。

```bash
# 示例：改版前，按着陆页分组的跳出率和每会话浏览数（property 为数字 ID，待确认）
curl -s -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  "https://analyticsdata.googleapis.com/v1beta/properties/$GA4_PROPERTY:runReport" \
  -d '{
    "dateRanges": [
      {"startDate": "2026-10-24", "endDate": "2026-11-20", "name": "before"},
      {"startDate": "2026-11-23", "endDate": "2026-12-20", "name": "after"}
    ],
    "dimensions": [{"name": "landingPage"}, {"name": "sessionDefaultChannelGroup"}],
    "metrics": [
      {"name": "sessions"}, {"name": "engagementRate"}, {"name": "bounceRate"},
      {"name": "screenPageViewsPerSession"}, {"name": "userEngagementDuration"}, {"name": "activeUsers"}
    ],
    "limit": 10000
  }'
```

拿到结果后按「关键页」的正则在本地分组，汇总时注意两点：

- **会话类指标**（跳出率、互动率、每会话浏览数）：用各行的会话数加权，或者先把分子分母各自加总再相除。不要直接平均各行的比率。
- **用户类指标**（每用户浏览数、平均互动时长）：分母是活跃用户，同一个用户会出现在好几行里，按行加总会重复计数。这类指标要在 API 请求里用 `dimensionFilter` 按正则筛出目标组，让 GA4 直接算出这一组的值；不要在本地合并。
