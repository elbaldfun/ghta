# StarRank 产品设计说明（多源版）

> 写于 2026-10-13。配套：[REDESIGN.md](REDESIGN.md)（架构）、[PRODUCT-REVIEW.md](PRODUCT-REVIEW.md)
> （产品判断）、[design/wireframes.html](design/wireframes.html)（线框，GitHub 与 iOS 对照）。
> 范围：信息架构、URL、四个页面模板、组件收敛。视觉令牌（色彩 / 字体 / 圆角 / 明暗）不改。

---

## 一、设计目标

1. 访客 5 秒内看出"这个站告诉我什么在真涨，覆盖哪些平台"。
2. 任何一个源（GitHub、iOS、Android、Chrome、HF）接入时，**不新增页面模板**，只填槽位。
3. 每个页面都有至少一个可做的动作（订阅、复制徽章、看被过滤的、切国家）。
4. 核心信号（增长、名次变化、质量档位、可疑）有统一且醒目的视觉表达。

---

## 二、信息架构

### 2.1 一级导航（5 项）

| 入口 | 回答的问题 | 下属 |
|---|---|---|
| **今天在涨** `/today` | 现在什么在冒头（跨源） | 按源分区的真涨 Top；可疑爆款；新进前 1000 |
| **GitHub** `/github` | 某领域最好的开源项目 | 领域树 / 语言 / 形态；开发者；AI 生态与话题并入二级 |
| **应用** `/apps` | 找能装的软件（跨平台货架） | 货架树 × 平台（开源桌面 / iOS / Android / 扩展）；替代品 |
| **扩展** `/chrome` | 浏览器扩展榜 | 商店分类 × 国家 |
| **模型** `/models` | 模型榜 | 任务组 |

搜索框全局，跨源；结果按源分组。"洞察"（博客）降为页脚与首页栏目入口，不占一级。
iOS / Android 商店榜在"应用"入口下以平台切换呈现，而不是再加两个一级入口；"扩展"独立是
因为它的受众（开发者 / 效率用户）与手机应用不重叠，且分类树完全不同。

### 2.2 维度模型

每个列表页的筛选都由这五个维度组合，顺序固定，不存在的维度隐藏：

```
源 source → 国家 country（仅商店类） → 分类 category（按源的树）→ 形态/平台 facet → 时间窗 window
```

界面语言（8 种）与国家分开：日本用户可以看美区榜。

### 2.3 URL 规则

| 模式 | 示例 | 说明 |
|---|---|---|
| `/{source}` | `/github` `/chrome` | 源首页 = 该源的"今天在涨 + 总榜" |
| `/{source}/c/{path}` | `/github/c/ai/agents` `/ios/c/productivity` | 分类落地页，静态可索引 |
| `/{source}/l/{lang}` | `/github/l/rust` | 仅 GitHub |
| `/{source}/t/{facet}` | `/github/t/cli` | 形态 |
| `/{source}/{id…}` | `/github/mattpocock/skills` `/ios/id1234567` `/chrome/{extId}` | 详情 |
| `/apps/s/{shelf}` | `/apps/s/productivity/notes` | 跨平台货架页；`?platform=ios` 过滤 |
| `/apps/alternatives/{slug}` | `/apps/alternatives/notion` | 跨平台替代品 |
| `/developers`、`/developers/{login}` | | 人物页 |
| `/badge/{source}/{id}.svg` | | 徽章 |
| 国家 | `?country=jp` | 商店类源的查询参数，默认按用户地区推断，可记住 |

现有 `/?category=…`、`/repo/{owner}/{name}`、`/breakout`、`/ecosystem`、`/topics`、`/map`
全部 301 到新路径。

## 三、四个页面模板

每个模板固定五个区域：**标题区 / 筛选区 / 主列表 / 侧栏 / 动作区**。模板之间只换槽位内容。

### 3.1 榜单页（Board）

用于：源首页、分类页、语言页、形态页、扩展榜、模型榜、开发者榜、今天在涨。

| 区域 | 内容 | 按源变化的槽位 |
|---|---|---|
| 标题区 | 面包屑（源 › 分类）、H1、一句话描述、条目数 | 描述文案（"按 star 与 7 日增长排名" / "按美区免费榜名次"） |
| 筛选区 | 维度顺序：国家 › 子分类 chips › 形态/平台 › 排序 | 国家选择器仅商店源；形态仅 GitHub；平台仅应用 |
| 主列表 | `EntryRow` 列表，默认 24 行，分页 | 主指标、增长表达、次要指标 |
| 侧栏（桌面） | 分类树；手机折叠为选择器 | 树的来源 |
| 动作区 | 订阅本榜（RSS / 邮件）、"已过滤 N 个可疑条目，查看" | — |

默认排序：**真涨优先**（7 日增长，质量 A/B），总榜作为第二个 tab。资料类形态（awesome /
tutorial / interview）在增长排序下默认排除，单独一个"资源"形态页。

### 3.2 详情页（Entry）

| 区域 | 内容 | 按源变化的槽位 |
|---|---|---|
| 标题区 | 图标、名称、作者/开发者、外链、**名次行**（总榜 #、分类 #、↑N 本周） | 名次行的榜单名 |
| 信号区 | 四格关键指标 + 增长曲线 + **质量档位卡**（A–D + 三条理由） | 指标组：star/fork/issue/周增 ↔ 名次/评分/评论数/价格 ↔ 用户数/评分 |
| 主体 | 来源内容 | README ↔ 截图轮播 + 商店描述 + 评分分布 ↔ 模型卡 |
| 侧栏 | 作者卡（其他作品、X、公司）、同类条目（同货架 / 同分类，质量加权 6 个）、替代关系 | 作者 ↔ 开发者账号 |
| 动作区 | 复制徽章、订阅更新、跨平台替代（"这个 iOS 应用的开源替代"） | — |

### 3.3 货架页（Shelf）

用于：`/apps`、`/apps/s/{shelf}`、替代品页。跨源，是唯一以"用途"而非"源"组织的模板。

| 区域 | 内容 |
|---|---|
| 标题区 | 货架名、一句话用途、平台覆盖徽标（开源 / iOS / Android / 扩展各有多少） |
| 筛选区 | 平台 › 操作系统（开源桌面时） › 排序（真涨 / 热门 / 新发布） |
| 主列表 | `EntryCard`（有截图）或 `EntryRow`，同一货架内不同平台混排，行首有平台徽标；同一开发者最多连续出现 2 个 |
| 侧栏 | 货架树（11 × 46） |
| 动作区 | 订阅货架、"最佳 X"合集入口 |

### 3.4 人物页（Person）

用于：`/developers`（榜单模式）、`/developers/{login}`（详情模式）。

| 区域 | 内容 |
|---|---|
| 标题区 | 头像、名字、X 账号（行首，可点）、公司、领域标签 |
| 信号区 | 作品总 star、本周增长、质量档位（作品的平均）、上榜次数 |
| 主体 | 作品列表（`EntryRow`，跨源：GitHub 仓库 + 未来的商店应用同一开发者） |
| 动作区 | 分享卡片（"AI builder 本周 #3"，1200×630 图），这是上榜者会主动转发的东西 |

榜单模式的行：头像、名字、X、代表作、增长、质量；"上升"榜要求 ≥ 2 个作品或 A/B 档。

### 3.5 首页 `/`

不是榜单页。三段：
1. **今天在涨**：按源分四列（GitHub / 应用 / 扩展 / 模型），每列 5 条真涨，带"查看本源"。
2. **本周可疑爆款**：3 条，带理由，链到"可信信号"说明页。这是站点的差异化在首页的直接体现。
3. **领域热度**：现有热力图压成一行色块，点击进分类页。
下方：洞察栏目最新 3 篇、订阅入口。

## 四、组件收敛

| 组件 | 替代现有 | 槽位 |
|---|---|---|
| `EntryRow` | RepoRow、RankTable 行、BreakoutBoard 行、ModelRow、DeveloperCard（榜单模式） | 图标、标题、副标题、标签组、`Metric`×3、`SignalChip`、行尾动作 |
| `EntryCard` | AppCard、RepoCard | 截图、图标、标题、tagline、平台/下载、`SignalChip` |
| `SignalChip` | 散落的 "+1.8k ★/day" 文本 | 类型：growth / rankDelta / quality / suspicious；颜色用现有 `--up/--down/--heat*` |
| `Metric` | 四格指标 | 标签、值、方向、单位 |
| `FilterBar` | FilterBar、FilterDropdown、PageTabs 的组合 | 维度数组，按源渲染 |
| `DimensionTree` | CategoryTree | 树来源（领域 / 货架 / 商店分类） |
| `ActionBar` | 无 | 订阅、徽章、分享、查看过滤 |
| `CountryPicker` | 无 | 仅商店源 |
| `SourceBadge` | PlatformBadges | 源图标 + 平台，用现有 `--source-*` 令牌 |

删除：HotBar、Carousel（并入首页"今天在涨"）、EcosystemMap（并入分类页侧栏）、NavDropdown。

## 五、信号的视觉语言

| 信号 | 表达 | 位置 |
|---|---|---|
| 增长 | 绿色 `SignalChip` "+1.8k ★ / 7d" 或 "↑12 名" | 行尾、详情信号区 |
| 名次变化 | 箭头 + 数字，与增长并列 | 详情名次行、徽章 |
| 质量档位 | A/B 不显示（默认可信），C 灰色标签，D 橙色标签 + "可疑" | 行首图标角标、详情质量卡 |
| 被过滤 | 列表尾部一行灰色"已折叠 N 个可疑条目 · 查看" | 榜单页动作区 |
| 源 | 行首小图标，颜色用 `--source-*` | 跨源列表（首页、货架、搜索） |

---

## 六、响应式与无障碍

- 断点沿用：`lg` 以上侧栏并排，以下折叠为选择器；`EntryRow` 在手机上两行（标题行 / 指标行）。
- 所有 `SignalChip` 带文字，不只靠颜色；质量档位有 `aria-label`。
- 国家与语言切换都在页头，记住上次选择（localStorage）。

## 八、实施顺序

1. 路由与导航（URL 表、301、新页头）—— 不依赖架构，立即。
2. `EntryRow` / `SignalChip` / `FilterBar` 三个组件，先替换 GitHub 的七个列表页。
3. 详情页改模板（名次行、质量卡、动作区）—— 依赖架构阶段 2。
4. 货架页跨平台化、人物页 —— 依赖第一个商店源接入。
5. 首页"今天"视角 —— 依赖 `labels.quality`。

每步单独 PR，布局守卫脚本扩展为"模板守卫"：新页面必须使用四个模板之一。
